# STRICT_KEY_01: strict TT search key

Status 2026-09-25: **REJECT_AS_DECLARED / NOT_PROMOTED.** The screen met this
hypothesis's declared falsifier, a repeatable fixed-depth slowdown
([results](#screen-results)). The Linux match was stopped and is
INCONCLUSIVE ([result](#linux-match-result-stopped)). No Elo gain is
established. Production, the GUI release, the accepted DLL and the default
build are unchanged. The candidate stays in source behind
`MAKHOS_STRICT_SEARCH_POSITION_KEY=1`, as it was before this work.

## Hypothesis

The injective XOR salt removes the deterministic false TT hits and cutoffs of
the legacy OR-salted key. It does so without a meaningful throughput cost and
without losing strength in paired play.

It is falsified by either of two results:

- a repeatable fixed-depth slowdown;
- a significant paired loss.

It is a correctness fix first. Any Elo gain is a secondary question that only
paired games can answer.

## The defect

`search_position_key()` (`native/makhos_native.c`) mixes two components:

- the red/black occupancy;
- a packed state of `kings << 17 | turn << 9 | reversible_plies`.

The legacy build salts the state with `state | 0x9e3779b97f4a7c15`. OR erases
every state bit that is already 1 in the salt. That covers 21 of the 32 king
flags and several clock bits, so two positions that differ only in those
bits get the same 64-bit key.

The main TT trusts the key alone. The engine therefore reuses bounds from a
different position, for example the same squares with a man where the
position has a king. This is a deterministic alias, not a random hash
collision. See the [2026-08-20 ledger entry](../../.agents/skills/thai-makhos-engine/references/experiment-evidence-ledger.md)
and the [game 2139e329 review](../game_reviews/2139e329d3c5def3/README.md).
That review measured 8,414 false cutoffs, 593 of them between different king
masks, across three roots of a lost NNUE game at depth 20. The strict key had 0.

The C4 endgame search has no TT, so the defect is confined to the main native
search. That covers the middlegame and the 7–10 piece band, where the
practical no-loss track expects the opponent to be exact.

## Screen: false cutoffs and fixed-depth behavior

[`screen.py`](screen.py) builds the control, strict and two TT-alias audit
libraries from current source. The audit libraries are generated by the
2139e329 review's `instrument_tt.py` and are never used for timing or play.

It searches a seeded, train-split-only selection from
`corpora/nnue_quiet_leaf_pilot_v4.jsonl`. Validation and test rows are never
read into the selection. The run uses 64 positions with kings and 7–12 pieces,
and 64 king-free positions with 13 or more pieces. Every search uses depth 20,
hash power 20, NNUE v1, a fresh context and project rules. Control and strict
alternate order over three repetitions.

Results: see [the results section](#screen-results) below.

## Linux non-regression match (STRICT_KEY_01-L1)

The contract, [`contract_l1.json`](contract_l1.json), was declared at
2026-09-25T16:01:10Z against commit `e406bd8`, before any game was played.

- Players: the same-source strict library against the control, NNUE v1, one
  thread each, persistent search, hash power 20.
- Conditions: **no tablebases**, project rules, 2s+0.02s, 6 random opening
  plies with colours swapped, seed 20260925, two parallel games.
- Test: pentanomial SPRT with H0=-3 and H1=+1 Elo, alpha = beta = 0.05, capped
  at 3,000 pairs.

It answers only whether the strict key is a regression in no-tablebase
single-thread play. It is not the Windows acceptance gate.

be resumed ([result](#linux-match-result-stopped)).


**Verdict: REJECT_AS_DECLARED / NOT_PROMOTED.** The strict build searches
3–14% more nodes at equal depth and takes 1.147× and 1.037× the total time.
That is the repeatable fixed-depth slowdown this hypothesis declared as a
falsifier. An earlier version of this section argued that fixed-depth results
cannot settle strength and that the paired match decides. That changed the
declared criterion after the result was known, and it is withdrawn. The screen
remains valid correctness evidence: the strict key removes every false hit and
cutoff.

The clock aliases are mostly benign far from the 80-ply limit. The king-mask
aliases can substitute a man for a king. The screen does not separate their
playing impact.
