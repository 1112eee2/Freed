## 4. ประเด็นพัฒนาเอนจิ้นที่เกมนี้เปิดเผย

### A. รอยต่อ 8 ตัวกินเข้าฐาน 6 ตัว — หลักฐานชัดที่สุด

ก่อนพลาย 51:

`B:BM23,26:BK15:RM13,14,19,21,27`

ตา `15x24x31` กินสองตัว เหลือ `R:BM23,26:BK31:RM13,14,21` ซึ่ง TB6 ยืนยัน DRAW ทันที แต่เกมบันทึก `native-root-split`, TB hits 0, score +214, WDL UNKNOWN; หลังแดง `21-25` พลาย 53 จึงเปลี่ยนเป็น `native-endgame` และ score 0 / DRAW

ใน source ที่ตรวจ `NativeEndgameSearch.supports_position()` รับ root ไม่เกิน 6 ตัว และกรณี **7 ตัว** ที่กินเข้าฐานเท่านั้น จึงปฏิเสธ root 8 ตัวนี้ ส่วน `Engine._can_use_native_search()` ยังส่ง root เกิน exact limit ไป legacy search ข้อมูลในเกมสอดคล้องกับช่องว่างนี้

ช่องว่างกว้างกว่าตาเดียว: PV เดิมพลาย 47, 49 และ 51 เข้าตำแหน่ง TB DRAW เดียวกันภายใน 5, 3 และ 1 พลาย ตามลำดับ แต่รายงานคะแนน +294, +207, +214 และไม่มี TB hits แม้เพิ่มเวลา 1T เป็น 5 วินาที พลาย 51 ยังให้ scalar −39 กับตาที่ raw TB ยืนยัน DRAW นี่ไม่ใช่หลักฐานว่า NNUE ใช้งานไม่ได้ แต่ยืนยันว่าระบบเส้นทางนี้ยังไม่ได้บังคับคะแนนด้วยผล TB

### B. ข้อมูลประจำ backend ช่วง endgame ใน saved game ยังไม่ครบ

ทั้ง 12 ตา `native-endgame` ไม่ได้เก็บ `native_endgame_library`, SHA ของ endgame DLL, effective endgame threads หรือ explicit WDL lower/upper ส่วน `native_library_sha256` ที่มีอยู่เป็น DLL กลางเกมเดิม แม้ช่อง `threads` จะเป็น 12 ก็ยืนยันจากไฟล์นี้เพียงอย่างเดียวไม่ได้ว่า endgame ใช้ C3 1T หรือ C4 หลายเธรด

`server.engine_search_provenance()` ส่งข้อมูล endgame บางส่วน แต่ whitelist ของ engine metadata ใน `web/app.js` ยังไม่คัดลอกลงบันทึกเกมครบ และ API ยังต้องเพิ่ม hash ของ DLL endgame ให้ระบุ artifact ที่รันได้จริง เรื่องนี้จำกัดการทำซ้ำเหตุการณ์ มิใช่หลักฐานว่า backend ผิดในเกมนี้

### C. อย่าอ่านกราฟคะแนนที่ผสม forced move เป็นความผิดพลาด

เกมมี backend `forced` 6 ตา ตัวอย่างพลาย 33 ได้ +31 จากทางลัด forced/HCE แล้วพลาย 35 ได้ −215 จาก NNUE search จึงไม่ควรเรียกส่วนต่าง −246 ว่า blunder ตาเดียว เปรียบเทียบ search ที่ใกล้กันคือพลาย 31: −66 กับพลาย 35: −215 ซึ่งก็ยังมีการเดินหลายตาคั่นและไม่ใช่ counterfactual root analysis

### D. เวลาไม่ใช่สาเหตุที่มีหลักฐานรองรับในเกมนี้

กลางเกมที่เสียเปรียบใช้ 2 วินาทีทั้งหมด; เปลี่ยนเป็น 1 วินาทีตั้งแต่พลาย 57 ซึ่งอยู่ในช่วง TB DRAW แล้ว ให้เชื่อ per-move metadata แทนค่า 1 วินาทีใน header ตอนเซฟ

ทั้งเกมมี native-root-split 23 ตา, native-endgame 12 ตา, forced 6 ตา ไม่พบ Python fallback หรือ native error เวลาค้นหาเกิน budget สูงสุด 21 ms และ setup แต่ละตาอยู่ 0.726–1.281 ms จึงไม่พบอาการค้างโหลดฐานหรือหล่น Python ที่อธิบายช่วงเสียเปรียบ อย่างไรก็ตามเวลานี้เป็นค่าที่บันทึกในเกม ไม่ใช่การทดสอบ latency ใหม่ และไม่มี telemetry ภาระระบบในขณะเล่น

## 5. งานวิจัยต่อที่ควรทำตามลำดับ

1. **เพิ่ม fixture รอยต่อ 8→6 ของพลาย 51**: เมื่อเปิด native endgame ให้ตรวจการกินหลายตัวเข้าฐานโดยไม่จำกัดว่าต้องเริ่มจาก 7 ตัว ตาที่เข้าฐานต้องได้ WDL/score ตาม proof ก่อน NNUE รักษา root policy เดิมและ default-off จนผ่าน gate รวมกรณี flag-off, history ซ้ำ, clock ใกล้ 80 และทางเลือกที่ยังอยู่นอก TB ห้ามแก้ด้วย raw WIN cutoff
2. **เติม saved-game provenance**: บันทึก DLL endgame จริงพร้อม SHA, requested/effective threads, WDL lower/upper, source revision และข้อมูล root candidates เท่าที่ทำได้ เพื่อแยก evaluation error ออกจาก routing/SMP และ replay ได้ตรงเงื่อนไขกว่าเดิม
3. **สอบสวนตำแหน่งกลางเกม 25/27/35/41/42**: เปรียบเทียบทุก root move ที่ common depth เดียวกันด้วยรุ่น NNUE เดิม แยก 1T กับ production 12T, ระบุ cold/warm TT และทดสอบ 2/5/20 วินาทีบนเครื่องว่าง ให้ความสำคัญกับ `32-28` เทียบ `31-27` และผลแดง `21-25` เทียบ `20-24`; การอ่าน PV เส้นเดียวไม่พิสูจน์ค่าทั้ง root
4. **ตรวจ TB ใน subtree ของ root ใหญ่ต่อไป**: fixture PV พลาย 47/49 แสดงว่ามองเห็นผลเสมอได้หลังการกินไม่กี่พลาย ไม่ควรคาดหวังว่าเพิ่มเวลา NNUE อย่างเดียวจะแก้ช่องว่างนี้ได้สม่ำเสมอ ต้องพิสูจน์ parity, overhead กลางเกม และความปลอดภัยของ history ก่อนเปิด production
5. เก็บเกมนี้เป็น external-human case study พร้อมกลุ่ม `unique TB draw`, `scalar zero vs WDL interval`, `8-to-6 capture`, `promotion race`, `repetition-safe conversion`; ไม่นำเกมเดียวไปปรับ NNUE แล้วอ้างว่าเพิ่ม Elo การเปลี่ยน strength ต้องมีชุดแยกและ paired/SPRT ตามนโยบายเดิม

สถานะ: **เก็บเป็นหลักฐานวิจัย**; ยืนยันการป้องกันและจุดพลิกท้ายเกมแล้ว ส่วนความผิดพลาดต้นเหตุในกลางเกมยัง **INCONCLUSIVE** ไม่มีการ promote candidate หรือเปลี่ยนการตั้งค่า GUI ในงานนี้
